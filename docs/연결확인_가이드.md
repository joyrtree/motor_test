# 연결 확인 가이드 (라즈베리파이 4 · Ubuntu 24.04)

배선이 제대로 됐는지 라즈베리파이에서 확인하는 순서입니다. 위에서부터 차례대로 하면 됩니다.

| 확인할 것 | 쓰는 파일 |
| --- | --- |
| 장치가 꽂혀서 보이는지 | `codes/check_connections.sh` |
| 센서 값 (GY-85, GPS, 레이더, 카메라) | `setuptest.py` (팀 레포 s1_patrol_robot 에서 가져온 파일) |
| 모터 + 엔코더 + ESP32 통신 | `esp32/motor_encoder_test/motor_encoder_test.ino` + `codes/motor_test.py` |

---

## 0. 처음 한 번만

라즈베리파이 터미널에서:

```bash
sudo apt update
sudo apt install -y git python3-serial python3-smbus i2c-tools
sudo usermod -aG dialout $USER      # 시리얼 포트 권한. 실행 후 로그아웃했다가 다시 로그인

git clone https://github.com/joyrtree/motor_test.git
cd motor_test
```

이미 받아둔 폴더가 있으면 `cd motor_test` 후 `git pull`.

## 1. 장치가 보이는지 한 번에 확인

```bash
bash codes/check_connections.sh
```

| 항목 | 정상일 때 |
| --- | --- |
| USB 시리얼 | 2개 (ESP32, 레이더용 CP2102 어댑터) |
| GPS UART | `/dev/serial0` 또는 `/dev/ttyS0` 있음, 시리얼 콘솔 꺼져 있음 |
| I2C | 표에 `53`, `68` 이 보임 (GY-85 가속도, 자이로) |
| 카메라 | `/dev/video0` 등이 보임 |
| ROS 2 | `/opt/ros/` 아래 배포판 이름 |

`[확인]` 이라고 뜬 줄만 고치면 됩니다.

---

## 2. GPS 쓰기 전에 (Ubuntu 는 꼭 해야 함)

Ubuntu 는 GPIO14/15 UART 를 "시리얼 콘솔"로 쓰고 있어서, 그대로면 GPS 값이 안 읽힙니다. 1번 결과에 "시리얼 콘솔이 GPIO UART 를 쓰고 있음" 이 뜨면:

```bash
sudo cp /boot/firmware/cmdline.txt /boot/firmware/cmdline.txt.bak   # 백업
sudo sed -i 's/console=serial0,115200 //' /boot/firmware/cmdline.txt
sudo reboot
```

## 3. 센서 값 확인 (`setuptest.py`)

레이더는 USB-UART 어댑터(CP2102)로 연결되어 있어서 포트 이름을 알려줘야 합니다.

```bash
ls -l /dev/serial/by-id/
```

ESP32 와 CP2102 어댑터가 둘 다 `Silicon_Labs_CP210x...` 처럼 비슷한 이름으로 보일 수 있습니다. 헷갈리면 **ESP32 USB 를 잠깐 뽑고** 다시 확인하세요. 남아 있는 게 레이더 어댑터입니다.

```bash
python3 setuptest.py --duration 30 --radar-port /dev/serial/by-id/<레이더 어댑터 이름>
# /dev/serial0 이 없고 /dev/ttyS0 만 있으면 뒤에  --gnss-port /dev/ttyS0  추가
```

| 줄 | 뜻 |
| --- | --- |
| `[IMU] [DATA] accel_mps2=(..., ..., +9.8)` | GY-85 정상. 평평하게 두면 z 가 약 9.8 |
| `[GNSS] [DATA] NMEA received ... invalid` | **배선은 정상.** 실내라 위치를 못 잡은 것. 창가/실외에서 몇 분 기다리면 `valid` |
| `[GNSS] [WAIT] no NMEA line` | GPS TX/RX 교차 연결, 2단계(시리얼 콘솔) 확인 |
| `[RADAR] [DATA] presence=...` | 레이더 정상. 손을 흔들면 moving 값이 바뀜 |
| `[RADAR] [WAIT] bytes_received_total=0` | 레이더 TX/RX 교차, 5V, 포트 이름 확인 |
| `[CAMERA] [ERROR] ...` | `/dev/video*` 가 보이면 배선은 정상이고 Ubuntu 에 카메라 프로그램(picamera2/rpicam-still)이 없는 것일 수 있음 |

## 4. 모터 + 엔코더 + ESP32 통신 (`motor_test.py`)

### 4-1. ESP32 에 펌웨어 넣기 (노트북 Arduino IDE)

1. `esp32/motor_encoder_test/motor_encoder_test.ino` 를 Arduino IDE 로 열기
2. 툴 → 보드 → **ESP32S3 Dev Module**, 포트 선택 → 업로드
3. 시리얼 모니터(115200)에 `$E,...` 줄이 계속 나오면 성공. 시리얼 모니터는 닫고 USB 를 라즈베리파이로 옮김

### 4-2. 배선 (USB, 배터리 뽑은 상태에서)

| ESP32 | 연결 |
| --- | --- |
| GPIO4 / 5 | MDD3A M1A / M1B (좌측 모터) |
| GPIO6 / 7 | MDD3A M2A / M2B (우측 모터) |
| G | MDD3A GND |
| 3V3 | 좌·우 엔코더 V (**5V 아님**) |
| G | 좌·우 엔코더 C |
| GPIO9 / 10 | 좌측 엔코더 A / B |
| GPIO11 / 12 | 우측 엔코더 A / B |

모터선 M1/M2 → MDD3A 단자, 배터리 → 퓨즈 → VB+/VB−.

### 4-3. 실행

1. ESP32 'UART' 포트 ↔ 라즈베리파이 USB
2. **바퀴를 공중에 띄우기**
3. 배터리 연결
4. 실행:

```bash
python3 codes/motor_test.py
```

좌측만 → 우측만 → 둘 다 정회전 → 둘 다 역회전 → 정지 → 워치독 순서로 자동 진행하고, 마지막에 결과를 요약합니다. 끄기는 `Ctrl+C`, 그다음 **배터리 먼저** 뽑기.

| 결과 | 뜻 / 고칠 것 |
| --- | --- |
| `OK` | 정상 |
| `엔코더 신호 없음` | 그 쪽 엔코더 V(3V3)/C(G)/A/B 배선. 모터 자체가 안 돌면 MDD3A 배선/배터리 |
| `방향 반대` | 엔코더 A/B 선을 서로 바꾸기 |
| 1번(좌측만)에서 우측이 돎 | GPIO4·5 와 6·7 점퍼선이 바뀜 |
| 두 바퀴가 서로 반대로 돎 | 반대로 도는 모터의 M1/M2 선을 MDD3A 단자에서 바꾸기 |
| 워치독 `실패` | 펌웨어가 최신인지 확인 |
| `ESP32 를 못 찾았습니다` | USB 케이블(데이터용인지), 펌웨어 업로드, `ls /dev/serial/by-id/` |

### 통신 형식 (참고)

| 방향 | 메시지 | 뜻 |
| --- | --- | --- |
| 라즈베리파이 → ESP32 | `$M,<좌>,<우>*HH` | 모터 명령, -255 ~ 255 |
| 라즈베리파이 → ESP32 | `$R*HH` | 엔코더 카운트 0 으로 |
| ESP32 → 라즈베리파이 (50ms 마다) | `$E,<ms>,<좌카운트>,<우카운트>,<좌PWM>,<우PWM>,<워치독>,<체크섬오류수>*HH` | 상태 보고 |

`HH` 는 `$` 와 `*` 사이 글자를 XOR 한 체크섬(16진수 2자리). 체크섬이 틀린 명령은 버리고, 300ms 동안 정상 명령이 없으면 ESP32 가 스스로 모터를 멈춥니다.
